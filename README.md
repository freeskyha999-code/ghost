# GHOST · 游戏库

纯静态网站，部署在 GitHub Pages：https://freeskyha999-code.github.io/ghost/

每个游戏是一个独立文件夹，首页由数据自动生成。**新增游戏不需要修改 `index.html`。**

## 目录结构

```
index.html            首页（只负责显示，读取 games.json 和各游戏的 meta.json）
games.json            游戏登记表 + 标签中文名
games/<游戏>/          游戏文件夹（index.html 是游戏入口，meta.json 是游戏资料）
roulette/<游戏>/       同上（历史目录，保持原样，不要搬动）
script-mode/          独立的剧本模式工具，与游戏库首页无关，默认不要改
```

## 新增一个游戏（照这个做）

1. 在 `games/` 下建文件夹，**文件夹名用英文小写**（如 `games/my-game/`），里面放游戏入口 `index.html`。
2. 在同一文件夹放 `meta.json`（格式见下）。
3. 打开根目录 `games.json`，在 `games` 数组里加一行路径，如 `"games/my-game"`。
4. 如果用了新标签，在 `games.json` 的 `tags` 里补上「标签代号: 中文名」。
5. 提交。过一两分钟 Pages 部署完成，首页自动出现新卡片。

游戏页里请放一个返回链接：`<a href="../../">← 游戏库</a>`（游戏在二级目录时）。

## meta.json 格式

```json
{
  "name": "游戏中文名",
  "en": "ENGLISH NAME",
  "desc": "一两句话简介，会在卡片上显示两行。",
  "tags": ["horror", "strategy"],
  "status": "可玩",
  "platform": ["电脑", "手机"],
  "cover": "data:image/webp;base64,....",
  "added": "2026-10-14",
  "featured": false
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| name | 是 | 卡片标题 |
| en | 否 | 英文名，小字显示 |
| desc | 是 | 简介 |
| tags | 是 | 标签代号数组，代号要在 `games.json` 的 `tags` 里有中文名，否则直接显示代号 |
| status | 否 | `可玩`（绿点）或 `开发中`（黄点），默认 `可玩` |
| platform | 否 | 显示在卡片底部 |
| cover | 是 | 封面图，见下 |
| added | 否 | `YYYY-MM-DD`，决定「最新加入」排序 |
| featured | 否 | `true` 则成为首页大图精选。**同一时间只给一个游戏设 true**，没人设置时取列表第一个 |

## 游戏启动详情页（通用入口）

所有游戏统一通过根目录的 `play.html?game=...` 启动，不要给单个游戏另写启动弹窗。启动页根据游戏目录中的 `meta.json` 自动展示封面、图标、完整简介、亮点、操作方法、设备要求和提示；点“开始游戏”后尝试进入全屏，浏览器不允许时仍可以窗口模式继续。详细约定见 [游戏启动器架构文档](docs/game-launcher-architecture.md)。

`launch` 是可选的启动页资料对象。旧游戏无需一次性补齐所有字段；字段缺失时启动页会回退到现有 `cover`、`desc`、`tags`、`platform` 等字段。

推荐的新游戏 `meta.json` 结构：

```json
{
  "name": "游戏中文名",
  "en": "ENGLISH NAME",
  "desc": "用于游戏卡片的简短介绍。",
  "tags": ["story"],
  "status": "可玩",
  "platform": ["电脑", "手机"],
  "cover": "games/my-game/assets/cover.webp",
  "added": "2026-10-19",
  "featured": false,
  "launch": {
    "icon": "games/my-game/assets/icon.webp",
    "tagline": "一句能传达体验气质的短句。",
    "description": "完整介绍：游戏目标、主要玩法、体验特色和适合的游玩方式。",
    "features": ["特色一", "特色二", "特色三"],
    "controls": ["操作方式一", "操作方式二"],
    "requirements": ["需要的浏览器能力或权限"],
    "tips": ["开始前的实用提示"],
    "orientation": "landscape",
    "accent": "#c9f28b"
  }
}
```

| `launch` 字段 | 用途与规则 |
|---|---|
| `icon` | 可选。游戏图标；支持仓库根目录相对路径、HTTPS 图片或图片 data URI。未提供时使用 `cover`。 |
| `cover` | 可选，覆盖启动页使用的封面；未提供时使用顶层 `cover`。顶层 cover 同时继续供游戏库卡片使用。 |
| `tagline` | 可选。标题附近的一句话定位，不要替代完整简介。 |
| `description` | 建议填写。启动页完整简介，优先级高于顶层 `fullDesc`、`longDesc`、`description`、`desc`。 |
| `features` | 可选字符串数组，列出最多 6 个核心亮点；只写当前游戏确实实现的内容。 |
| `controls` | 可选字符串数组，说明键盘、鼠标、触摸或动作控制。缺失时显示通用操作提示，不阻塞启动。 |
| `requirements` | 可选字符串数组，列出必须的权限、设备能力或浏览器要求。只写真实需要的条件。 |
| `tips` | 可选字符串数组，提供开始前有帮助的提示。 |
| `orientation` | 可选：`landscape` 或 `portrait`。启动页展示建议，不强迫浏览器旋转。 |
| `accent` | 可选六位十六进制颜色，例如 `#c9f28b`；错误值会回退到默认主题。 |

**封面与图标不是同一个概念。** 新游戏建议提供一张宽幅封面和一张清楚可识别的小图标；只有封面时启动页会兼容使用同一素材。路径统一相对仓库根目录（与 `games.json` 同级），或使用完整的图片 data URI。不要在启动器代码里给每个游戏写死内容，也不要把游戏专属说明写进根目录 `play.html`。

### 启动页的体验原则

- **先认识游戏，再决定进入。** 标题、图标、封面和完整简介优先呈现；玩法亮点与操作信息辅助判断，不用一堆装饰标签抢占注意力。
- **全屏是明确选项，不是入场门槛。** 由用户点击开始时尝试申请全屏；请求失败仍加载游戏，并提供可再次尝试的全屏按钮。
- **启动过程必须可解释。** 显示加载状态；等待时间较长时提供继续等待和重新加载入口，避免黑屏让玩家以为游戏卡死。
- **游戏负责自己的权限。** 启动页如实展示元数据要求，但摄像头、麦克风、运动传感器等权限仍由实际需要它们的游戏在合适时机请求。
- **缺资料也不能阻断游戏。** 可选字段缺失或 meta.json 读取失败时使用安全回退；只有非法游戏路径才阻止启动。
- **手机与桌面自适应。** 桌面采用封面与详情双栏；窄屏切换为纵向布局。尊重减少动态效果的系统设置，并保留键盘焦点样式。

### 封面规则

- 封面写成 **data URI**（`data:image/webp;base64,...`），直接放在 `meta.json` 里，不需要单独的图片文件。
- `cover` 也可以写成**字符串数组**（每项一小段），首页会自动拼接。长图建议每 100 字符一项，便于核对。
- 推荐 16:10 或正方形，webp，300–700px，体积尽量小于 30KB。
- **绝对不要手抄 base64。** 用脚本从图片生成，写文件时用工具直接写入，不要靠肉眼复制，一个字符出错整张图就废了（这个事故发生过）。

## 给 AI 维护者的规则

1. **仓库所有者已授权：AI 可以直接提交到 `main`，不需要等待确认。** 但每次提交后要向用户说明改了什么，并完成第 5 条的回读校验。
2. 不要修改已有游戏文件夹里的内容，除非用户明确要求改那个游戏。
3. 不要把游戏卡片写死到 `index.html`，只改 `games.json` 和 `meta.json`。
4. 不要移动或重命名已有游戏文件夹（链接和缓存会失效）。
5. 每次推送后必须校验：把仓库里的文件下载回来，和本地逐字节比对（`cmp`）；封面图用图片库实际解码一次，确认能打开。
6. `meta.json` 和 `games.json` 必须是合法 JSON（不能有注释、不能有尾逗号）。推送前用 JSON 解析器检查。
7. 中文路径可以存在（历史游戏就是），新游戏请用英文文件夹名。
8. 首页用 `fetch` 读取 JSON，**直接双击打开本地文件会显示「加载失败」**，要本地预览请先启动静态服务（如 `python3 -m http.server`）。

## 推送前检查清单

- [ ] `games.json` 是合法 JSON，新路径已加入
- [ ] 新文件夹里有 `index.html` 和 `meta.json`
- [ ] `meta.json` 的 `cover` 由脚本生成，能解码出图片
- [ ] 标签代号都在 `games.json` 的 `tags` 里
- [ ] 只有一个 `featured: true`
- [ ] 推送后已回读比对，结果一致

## 不在这里的东西

- `script-mode/`：独立的剧本模式/导演模式创作工具，有自己的说明，默认不要修改。
- `.bootstrap/`：初始化相关文件，不要动。
