# GHOST 游戏启动器架构

本文定义 GHOST 所有游戏共用的“启动前详情页”。目标是让任何新游戏沿用同一套外观、全屏入口、加载状态和错误处理，并通过自己的 `meta.json` 提供差异化信息，而不是在启动器中写死每款游戏的名字与说明。

## 1. 设计目标

1. **信息完整且易于判断**：展示游戏名、英文名（如有）、图标、封面、完整简介、核心亮点、操作方式、设备要求和开始提示。
2. **跨游戏一致**：所有游戏都通过根目录 `play.html?game=<path>` 启动。
3. **字段渐进增强**：旧游戏只提供 `name / desc / cover / tags / platform` 也能进入；完整填写 `launch` 后展示更丰富信息。
4. **全屏不成为硬性门槛**：点击开始时尝试全屏；浏览器拒绝时仍进入游戏，并能再次尝试全屏。
5. **故障可解释、可恢复**：显示加载过程；慢加载时允许继续等待或重新加载；读取元数据失败时不伪装成成功，也不因此永久阻止游戏入口。
6. **游戏与平台职责分离**：启动器只负责介绍、启动容器和全屏操作；具体游戏负责自己的输入方式、游戏状态、相机/麦克风/运动传感器权限和游戏内帮助。

## 2. 架构总览

```text
GHOST 游戏库首页 (index.html)
  └─ 点击游戏卡片
      └─ play.html?game=games/<slug>
          ├─ 路径校验（只允许 games/ 和 roulette/ 下的单层游戏目录）
          ├─ 并行读取
          │   ├─ <game-path>/meta.json
          │   └─ games.json（标签名称映射）
          ├─ 启动详情 UI
          │   ├─ 封面与背景
          │   ├─ 图标、标题与状态
          │   ├─ 完整简介与标签
          │   ├─ 亮点、操作、设备要求、小提示
          │   └─ 开始 / 返回游戏库
          └─ 用户明确点击开始
              ├─ 同步发起全屏请求（浏览器允许时）
              ├─ iframe 加载 <game-path>/
              ├─ 显示启动加载层
              ├─ iframe 完成加载 → 进入游戏
              └─ 超时/拒绝 → 提供继续等待、重试或窗口模式
```

核心原则：**`play.html` 是通用渲染器，不是游戏资料库。** 游戏的名字、简介、操作和主题色都来自元数据；未来加入游戏通常只需新建游戏目录、补齐 `meta.json` 并登记到 `games.json`。

## 3. 职责边界

| 模块 | 负责内容 | 不应该负责 |
|---|---|---|
| `index.html` | 搜索/分类/排序游戏卡片；链接到通用启动器 | 不应硬编码每款游戏的启动页 |
| `games.json` | 游戏路径登记、标签中文名映射 | 不存放长简介或大量游戏专属文案 |
| `<game-path>/meta.json` | 展示资料、平台、封面和可选 `launch` 内容 | 不放启动器逻辑或可执行脚本 |
| `play.html` | 路径校验、元数据读取、通用详情布局、全屏与 iframe 加载流程 | 不针对单个游戏写死介绍，不假定所有游戏有同样的控制方式 |
| 游戏自己的 `index.html` | 实际玩法、游戏内权限、输入和游戏运行错误 | 不依赖启动器读取游戏内部 DOM |

## 4. 元数据协议

### 4.1 既有必需字段

- `name`：游戏显示名称。
- `desc`：游戏卡片使用的短简介，并作为完整简介的最低限度回退。
- `tags`：分类代号，由 `games.json.tags` 转成可读名称。
- `cover`：卡片封面及启动详情大图。兼容 data URI 字符串、分段字符串数组和仓库相对路径。
- `platform`、`status`、`en`、`added`：可选的设备、状态与补充信息。

### 4.2 可选的 `launch` 对象

推荐结构：

```json
{
  "launch": {
    "icon": "games/my-game/assets/icon.webp",
    "cover": "games/my-game/assets/cover.webp",
    "tagline": "一句描述游戏气质的话。",
    "description": "完整简介，包括游戏目标、玩法循环、体验特色和游玩方式。",
    "features": ["核心亮点一", "核心亮点二"],
    "controls": ["键盘/鼠标/触摸或动作操作说明"],
    "requirements": ["真实的设备要求或权限"],
    "tips": ["开始前有帮助的建议"],
    "orientation": "landscape",
    "accent": "#c9f28b"
  }
}
```

字段行为：

- `icon`：缺失时回退到封面。
- `cover`：缺失时回退到顶层 `cover`。
- `tagline`：缺失时用完整简介作为封面叠层说明。
- `description`：优先级高于顶层 `fullDesc`、`longDesc`、`description` 和 `desc`。
- `features`：显示最多 6 个要点；不提供则隐藏亮点区。
- `controls`：显示操作说明；不提供则显示通用“进入后按照游戏内提示操作”。
- `requirements` 与 `tips`：没有内容时隐藏对应区块。
- `orientation`：支持 `landscape` / `portrait` 的体验建议，不强制旋转屏幕。
- `accent`：只接受 `#RRGGBB` 格式；无效值回退到默认主题色。

**素材路径约定**：相对路径以仓库根目录（`games.json` 所在目录）为基准。大封面与小图标可以分开；如果暂时只有一个图，启动器会兼容复用封面。启动器不应自己生成替代贴图或游戏素材。

## 5. UI 布局与体验原则

### 桌面

- 左栏：游戏封面，轻量背景氛围，状态标记。
- 右栏：标题/图标、英文名、完整简介、分类与平台、亮点、操作要求与提示。
- 底部：明确的主要动作“开始游戏 · 尝试全屏”，旁边保留返回游戏库。
- 启动器有游戏视觉识别感，但不通过过量特效、警告或标签给用户制造压力。

### 手机

- 自适应成单列，上方使用横向封面，详情信息向下阅读。
- 保持安全区域留白、按钮触控尺寸、窄屏换行与纵向滚动。
- 不假设设备一定支持全屏、键盘、鼠标或 AR。
- 尊重系统减少动态效果设置；所有交互按钮有清晰焦点状态。

### 文案与认知负担

- 先提供“这是什么游戏”和“你能做什么”，再展示技术要求。
- 仅显示与游戏相关的控制、权限和设备要求，不将所有可能的权限一概提示给用户。
- 不虚构游戏功能；如果资料缺少，显示诚实的通用提示。
- 主要按钮只有一个；返回是明确的次要操作；全屏失败属于可恢复状态，而非错误终点。

## 6. 启动状态机

```text
DETAILS
  └─ 用户点击主按钮
      └─ STARTING
          ├─ 并行请求全屏 + 设置 iframe.src
          ├─ 全屏成功 → 记录全屏状态
          ├─ 全屏失败 → 记录窗口模式备用提示
          └─ iframe load
              └─ PLAYING
                  └─ 顶部显示返回游戏库和全屏切换
          └─ 加载超时
              └─ SLOW_LOAD
                  ├─ 继续进入
                  └─ 重新加载
```

### 关键可靠性规则

- 全屏请求应直接源自用户点击事件，不能先等待网络请求再申请，以免丢失浏览器用户手势授权。
- 全屏请求失败不得取消游戏加载。
- 启动层在 iframe 完成加载后关闭；加载超时给出可理解的反馈和可恢复入口。
- 播放状态必须隐藏启动页的模糊背景和介绍层，避免挡住游戏内容。
- 返回库和全屏切换固定在播放状态的顶层。
- 对路径进行白名单校验，并拒绝 `..`、反斜杠和不在允许游戏目录下的地址。

## 7. 接入新游戏的流程

1. 在 `games/<slug>/` 添加游戏入口与资源。
2. 在该目录创建 `meta.json`，填写基础字段。
3. 推荐补齐 `launch.description`、`features`、`controls`、必要的 `requirements` 和 `tips`；图标最好与封面分开。
4. 在 `games.json` 的 `games` 数组登记该路径，并按需增加标签映射。
5. 检查 JSON 格式和素材路径后提交。无需更改 `play.html` 或首页的游戏卡片代码。
6. 从游戏库点击新卡片，验证详情页面、返回链接、窗口模式和全屏尝试。

## 8. 回归测试清单

- [ ] 元数据全部齐全的游戏：所有详情区正常显示。
- [ ] 仅有旧版基础字段的游戏：显示封面、标题、简介、平台/标签并能启动。
- [ ] 没有独立图标：回退显示封面。
- [ ] `cover` 是分段字符串数组：拼接后能显示。
- [ ] 相对路径封面和 data URI 封面均能显示。
- [ ] 没有 `meta.json` 或请求失败：详情页给出说明，允许尝试启动。
- [ ] 非法路径：拒绝进入，不构造任意 iframe URL。
- [ ] 浏览器支持全屏：用户点击后进入全屏。
- [ ] 浏览器拒绝/不支持全屏：游戏仍能进入，用户可以再次尝试。
- [ ] 慢速资源：显示超时提示、继续进入和重新加载。
- [ ] 桌面、窄屏、减少动态效果模式下，布局仍可读、按钮可操作。
- [ ] 进入游戏后启动背景不遮挡 iframe 内容。

## 9. 兼容性边界

启动器可以统一信息展示和全屏入口，但**不能把任意游戏自动改造成相同的玩法**。游戏自身仍需按真实需要处理摄像头权限、面部追踪、网络联机、音频播放、方向传感器及其错误提示。全屏是否可用取决于浏览器和用户操作；该架构提供优雅回退，不承诺绕过平台权限限制。
