**这整个过程大约 5-6 秒，期间屏幕什么都不动（HUD 显示但不能操作），双方都看到对方连接了但无法操作。用户可能把这5-6秒的等待误判成了"卡住"。**

但用户说"发消息也发不了"——聊天是 `CHAT_MSG`，server 只在 `inGame` 时转发，`inGame` 在 `checkReady` 里设为 `true`，也就是游戏开始后就可以。如果发消息也不行，说明 `room.inGame` 没被设为 `true`，或者消息根本没发出去。

**最可能的实际 bug：`CHAT_MSG` 在 game.js 里通过 `triggerLocalChat` → `sendNetMessage` 发送，但 `sendNetMessage` 用的是 `this.socket`，这个 socket 是 GameEngine 里的 `options.socket`，也就是 networkManager 传进去的 `this.ws`。如果 `this.ws` 在某个时刻被关闭或替换，消息就发不出去。**

但 `disconnect` 只在明确断开时调用，不应该自动触发。

**给你直接的 patch，修最有可能实际导致问题的地方：****找到了。`this.socket` 是 GameEngine 构造时从 `options.socket` 拿的，也就是 `networkManager.ws` 的引用。但 `networkManager._handleGameStart` 第152行替换了 `this.ws.onmessage`，ws 对象本身没变，socket 引用有效。**

**但是！`applyRoundSync` 第1386行只调 `updateUI()`，没调 `battle.startRoundAfterAnimation()`。**

此时 `battle.turn` 是什么？`applyRoundSync` 在 `battle.turn` 不确定的状态下调 `updateUI`，而 `updateUI` 里调 `startTimer`：

```js
startTimer() {
    clearInterval(this.timerInterval);
    if (this.battle.turn === 'animating') { this.ui.timer.innerText = '--'; return; }
    ...
}
```

**如果 `battle.turn` 是 `'animating'`（比如 `checkEmpty` 把它设成了 `'animating'` 然后等 `SYNC_ROUND`），那么 `applyRoundSync` 同步完数据后调 `updateUI`，timer 显示 `--` 然后直接 return，计时器不启动，按钮也因为 `isMyTurn = false` 而隐藏。游戏卡死。**

**这就是聊天、射击全部失效的原因：`applyRoundSync` 没有调 `startRoundAfterAnimation`。**

现在写 patch：确认了。`applyRoundSync` 里没有 `startRoundAfterAnimation`，也没有 `localSyncRound`。直接给 patch：

**game.js，第1377-1387行，`applyRoundSync` 函数，改成这样：**

```js
applyRoundSync(data) {
    this.battle.shells = data.shells || [];
    this.battle.playerItems = (data.eItems || []).map(i => ({...i}));
    this.battle.enemyItems = (data.pItems || []).map(i => ({...i}));
    this.battle.nextRoundTurn = data.nextTurn || 'host';
    this.battle.playerHp = data.enemyHp ?? this.battle.maxHp;
    this.battle.enemyHp = data.playerHp ?? this.battle.maxHp;
    this._rebuildSlots();
    this.scene.renderTableItems(this.battle.playerItems, this.battle.enemyItems);
    this.battle.startRoundAfterAnimation();  // ← 加这行
    this.updateUI();
}
```

**同时，server.js 里 `CHAT_MSG` 的转发有个问题，它被放在了需要 `room.inGame` 才能通过的 block 里：**

```js
case 'CHAT_MSG':
    if (!room.inGame) break;  // 游戏未开始聊天也发不了
```

聊天应该大厅里也能发，把 `CHAT_MSG` 单独提出来：

**server.js，在 `SYNC_ROUND/PLAYER_ACTION/FORCE_SYNC/CHAT_MSG` 这个 case block 里，把 `CHAT_MSG` 分离出去：**

```js
case 'CHAT_MSG':
    if (ws.roomId && rooms.has(ws.roomId)) {
        const room = rooms.get(ws.roomId);
        room.players.forEach(p => {
            if (p.ws !== ws && p.ws.readyState === WebSocket.OPEN) {
                try { p.ws.send(JSON.stringify(data)); } catch(e) {}
            }
        });
    }
    break;

case 'SYNC_ROUND':
case 'PLAYER_ACTION':
case 'FORCE_SYNC':
    if (ws.roomId && rooms.has(ws.roomId)) {
        const room = rooms.get(ws.roomId);
        if (!room.inGame) break;
        room.players.forEach(p => {
            if (p.ws !== ws && p.ws.readyState === WebSocket.OPEN) {
                try { p.ws.send(JSON.stringify(data)); } catch(e) {}
            }
        });
    }
    break;
```

**这两个改动加起来解决：**
1. `applyRoundSync` 不调 `startRoundAfterAnimation` → turn 卡在 `animating` → 所有操作失效（**这是卡死主因**）
2. 聊天在 `inGame` 检查里被拦掉（次要问题，但游戏中如果 `inGame` 有任何问题聊天也会失效）
